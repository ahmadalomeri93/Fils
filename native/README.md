# Hawwesh iPhone app (Capacitor shell)

The iPhone app is the website in a WKWebView, built with Capacitor 8.5.3 and Swift Package Manager (no CocoaPods).
Bundle id `com.hawwesh.app` (decided by the founder's COO; it is permanent after the first upload to App Store Connect), name «حوّش»,
iPhone only, iOS 15.4 and later, portrait only.

There is one copy of the web app: `dist/`. `scripts/stage-web.mjs` copies it into `native/www` (git-ignored) and changes
only what the app shell needs. The website itself is never touched.

## Status

iOS cannot be compiled on Linux, so nothing here has been compiled or run on a device. What is verified without a Mac:
`npm test` in this folder (project file structure, reproducible patch, Info.plist, privacy manifest, icon, dependency
pins, CI safety) and the web tests in `../tests` (native bridge with mocked plugins, e2e with a stubbed `window.Capacitor`).
The first real verification is the `iOS build (simulator)` workflow (see `../.github-workflows-draft/`).

## How the project is made (scaffold route)

`ios/` was generated on Linux with `npx cap add ios` (works without Xcode when using SPM) and is committed.
`scripts/patch-ios.mjs` turns the generated project into the Hawwesh app. It is idempotent and reproducible:
`tests/ios-project.test.mjs` patches a pristine Capacitor 8.5.3 project (`tests/fixtures/`) and requires the result to be
identical to what is committed.

Why this route: a committed project can be reviewed and built by CI without a generation step, and because the patch is a
script (not hand edits) a Capacitor upgrade is `regenerate, patch, run the tests`.

The patch:

- adds `overlay/App/*` to the app target: `HawweshBiometricsPlugin.swift` (Face ID / Touch ID through LocalAuthentication,
  biometrics only, never the device passcode), `HawweshViewController.swift` (registers that plugin, light status bar text)
  and `PrivacyInfo.xcprivacy` (UserDefaults CA92.1 for Preferences, FileTimestamp C617.1 for Filesystem, no tracking, no collected data)
- iPhone only, iOS 15.4 (`<dialog>` needs WebKit 15.4), version 1.0.0, Arabic as development region
- writes `Info.plist`: Arabic Face ID and camera usage text, `ITSAppUsesNonExemptEncryption=false`, portrait only, arm64
- blank launch screen (no Capacitor splash), icon from `assets/icon-1024.png` (1024x1024, no alpha, checked by `apply-icon.mjs`)

## Everyday commands

```sh
cd native
npm ci --ignore-scripts          # exact versions from package-lock.json
npm run sync                     # stage ../dist into www, then cap sync ios
npm run verify                   # is ios/ patched?  (npm run patch applies it)
npm test                         # checks that need no Mac (run it AFTER npm run sync, see below)
```

`npm test` reads files that only exist after the sync (`ios/App/App/capacitor.config.json` and `ios/App/App/public/`, both
git-ignored and generated by `cap sync`). On a clean checkout the order is therefore always
`npm ci --ignore-scripts`, `npm run sync` (or `node scripts/stage-web.mjs && npx cap sync ios`), `npm run verify`, `npm test`.
Both CI drafts run the steps in that order. Run before the sync, `npm test` stops with `ENOENT ... capacitor.config.json`.

On a Mac: `open ios/App/App.xcodeproj`, pick an iPhone simulator, Run. Or let CI do it.

Regenerating `ios/` from scratch (for example after a Capacitor upgrade):

```sh
rm -rf ios www && mkdir www && echo '<title>x</title>' > www/index.html
npx cap add ios && node scripts/patch-ios.mjs && npm run sync && npm test
```

If the generated template changed, the patch stops with a message naming the text it could not find.

## CI and TestFlight setup (founder, one time)

The two workflow drafts live in `../.github-workflows-draft/` (not in git yet; move them to `.github/workflows/` when approved).

- `ios-build.yml`: simulator build on every push to `ios-native`. No secrets. It is the first real compile check.
- `ios-testflight.yml`: manual run, archives and uploads with Apple's cloud-managed signing. Create the GitHub environment
  `appstore` (required reviewer), the secrets `APP_STORE_CONNECT_KEY_ID`, `APP_STORE_CONNECT_ISSUER_ID`,
  `APP_STORE_CONNECT_KEY_P8`, the variable `APPLE_TEAM_ID`, and the app record for bundle id `com.hawwesh.app`.
- **API key role: create a Team key with Access = Admin** (App Store Connect > Users and Access > Integrations > App Store
  Connect API > Team Keys). What is verified and what is not (pages fetched 2026-10-08):
  - Apple, WWDC21 session 10204 (https://developer.apple.com/videos/play/wwdc2021/10204/): Admin and Account Holder can cloud sign for
    App Store Connect distribution by default; a Developer needs the extra permission "Access to Cloud Managed Distribution
    Certificate". The same session names the flags `-allowProvisioningUpdates`, `-authenticationKeyPath`,
    `-authenticationKeyID`, `-authenticationKeyIssuerID`.
  - Apple (https://developer.apple.com/help/account/certificates/cloud-managed-certificates/): "Required role: Account Holder or Admin".
  - Apple (https://developer.apple.com/help/app-store-connect/get-started/app-store-connect-api/): team keys are generated by the Account Holder or an Admin.
  - Apple (https://developer.apple.com/documentation/appstoreconnectapi/creating-api-keys-for-app-store-connect-api): individual keys cannot use the Provisioning endpoints, so use a team key.
  - **Unverified**: no Apple page I fetched states which role an API key needs for `xcodebuild -exportArchive` cloud signing.
    A community report (https://developer.apple.com/forums/thread/698117, not Apple) says a Developer or App Manager key fails with
    "Cloud signing permission error" and an Admin key works. Also unverified: the ExportOptions keys (`method`
    `app-store-connect`, `destination` `upload`). The first run of the workflow is the real check.

## What the native build changes in the web app

All of it lives in `dist/native-bridge.js` and is loaded only when `window.Capacitor.isNativePlatform()` is true; the
website never loads it. See the header of that file for the contract. In short: Face ID toggle on top of the PIN, local
reminders (3 days before and 09:00 on the day, payday, max 60 pending), backup through the share sheet, a mirror of the
saved state in a native file that is restored if iOS clears web storage, no service worker, no install banners, external
links in the system browser.

### Native-only and web-only wording

Elements with the class `web-only` disappear inside the app (CSS `html.is-native .web-only`), `native-only` appear only in the app.
The iPhone Shortcuts help (the home link «طريقة الربط مع الآيفون», the «ربط إشعارات البنك» button, the Shortcuts section in
settings and `#bank-automation-dialog`) is web-only. The bank card keeps «جلب الإشعارات» and «لصق رسالة» in the app. In-app text must not say
browser, Safari or trial version, and must not name a commercial bank or use advisor wording: `tests/validate_static.py`
checks the source and `tests/native-shell.mjs` scans the visible text of every page and dialog in native mode.

### Hardening and checks added in the v40 review round

- Face ID gate (`createBiometricLock.authenticate`) returns true only when the plugin result is `{ success: true }`.
  A promise that resolves with `{ success: false }`, `undefined`, `null`, `{}` or a non-boolean `success` neither unlocks the app
  nor lets Face ID be enabled (tests: `tests/native-bridge.test.mjs`, `tests/native-shell.mjs`).
- Switch OFF track and thumb reach 3:1 in light and dark (`--switch-off: #7a859b`). `tests/contrast.mjs` now runs a second pass with a
  stubbed `window.Capacitor` so the native-only controls (Face ID and reminders switches in every state, the lock-screen Face ID
  button, the native privacy dialog) are measured, including a 3:1 check of switch track and thumb in both states.
- `dist/privacy.html` describes the web version and the iPhone app; web-only paragraphs carry `web-only` so the in-app copy has no
  browser wording. The final text with the contact placeholder is `/mnt/project-files/appstore/privacy-draft/privacy.html`: replace
  `{{CONTACT_EMAIL}}`, then copy it over `dist/privacy.html` and to the live privacy URL. `tests/validate_static.py` refuses any
  `{{` in `dist/privacy.html`.
